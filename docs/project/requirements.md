# Требования

## User Stories

### US-01. Отправка отзыва
Как клиент, я хочу отправить текст отзыва, чтобы его тональность была определена.

Критерии приёмки:
- Система принимает непустой текст и проверяет его язык перед анализом.
- Пустой текст отклоняется с сообщением об ошибке.
- К анализу допускается только текст, определённый как англоязычный. При другом или неопределённом языке модель не вызывается, результат не сохраняется и выводится сообщение «Поддерживаются только отзывы на английском языке».

### US-02. Определение тональности
Как оператор, я хочу видеть тональность отзыва, чтобы быстрее оценивать обратную связь.

Критерии приёмки:
- Результат содержит одну из трёх категорий тональности.
- При ошибке обработки система сообщает об этом.

### US-03. Просмотр результата
Как оператор, я хочу находить результат по идентификатору, чтобы повторно его просматривать.

Критерии приёмки:
- По существующему идентификатору отображается результат.
- Для неизвестного идентификатора выводится сообщение об отсутствии результата.

## UC-01. Анализ отзыва

**Актор:** клиент.  
**Цель:** определить тональность отзыва.  
**Предусловие:** клиент подготовил текст отзыва.

Основной сценарий:

1. Клиент отправляет текст отзыва.
2. Система проверяет, что текст непустой.
3. Система определяет язык и допускает к анализу только англоязычный текст.
4. Система передаёт текст модели.
5. Модель определяет тональность и возвращает результат.
6. Система сохраняет и показывает результат клиенту.

Альтернативные сценарии:

- Если текст пуст, система сообщает об ошибке.
- Если язык не английский или не удалось подтвердить английский язык, система не вызывает модель, не сохраняет результат и сообщает: «Поддерживаются только отзывы на английском языке». API возвращает HTTP 422.
- Если модель недоступна, система сообщает об ошибке.

**Результат:** тональность определена либо клиент получил сообщение об ошибке.
